# 平台适配与本地准备

在准备或修改启动材料、切换平台时读取。初始需求按 [主 skill](../SKILL.md) 的三组信息确认，先沿用已有回答；这里仅补充影响当前阶段的运行条件。计算方法、软件、运行位置和调度系统分别核对。

Codex 生成和修改的所有材料始终保存在本地。超算无法直接接入 Codex，采用“本地准备 → 用户传输/运行 → 用户回传 → 本地分析/回写”的交接方式；不要求远程连接，也不尝试用 SSH、MCP 或探测命令收集超算信息。计算本身在超算产生的输出不等于 Codex 在远端编写文件。

## 1. 依据当前阶段补充信息

先读项目记录、现有脚本和平台指南，只集中追问尚缺且会改变当前材料的信息。模板作为静态资料读取，不 source、不执行，也不据此自行登录或提交。不同阶段允许使用不同平台；远程工作站与本机是否受调度管理，均不能由位置推定。

| 情境 | 需要查明的内容 |
| --- | --- |
| 共同信息 | 阶段与任务、引擎/模型及版本、目标 OS/架构与 shell、CPU/GPU 需求、资源/时间上限、本地准备目录、实际运行目录 |
| MLIP | 实际 Python/容器环境、框架和权重位置、所需设备后端及兼容性、模型路径与运行配置；推理/优化/MD/训练分别记录 |
| VASP/DFT | 引擎版本与实际可执行文件、CPU/GPU 构建、编译器/MPI 环境、赝势来源、实际并行启动方式及兼容性 |
| 本机或无调度的工作站 | 环境启用方法、解释器/可执行文件位置、可用核数/设备/内存、工作目录和日志路径；不能按超算模板分配资源 |
| 受调度管理的机器 | 调度系统及其实现/版本、平台指定模板、分区/队列、账号/项目或 QoS（若要求）、节点/任务/线程/GPU 布局、内存和时限、module/环境/容器、工作与临时目录、日志及结果保留规则 |
| 远程运行 | 用于文档标识的平台别名、本地包与目标路径的对应关系、用户选择的传输和结果回收方法；仅本地准备不需要索取登录密码或密钥 |

只询问适用项。账号、QoS 等由平台规定是否必需；不强求不需要的字段。记录信息的来源与确认状态，区分用户提供、文档核实、旧模板和待确认项。

已有模板提供事实线索，核查机器、CPU/GPU 构建、资源和软件版本是否适用于当前任务；过期、冲突的配置先澄清。发现命令或软件包不代表许可证、模型适用性或实际部署已经验证。

## 2. 本地持久保存超算环境

普通本机平台配置仍可融入主方案；超算环境按用户要求独立持久保存。首次确定超算且获得实际信息时，建立本地 `docs/platforms/<稳定平台标识>.md`。已有 `docs/platform.md`、环境说明或用户指定档案覆盖同一平台时原位更新，不迁移、不另建竞争档案；不同超算或实质不同的账号/软件环境分别标识。尚无实际信息时只记录待确认，不生成假档案。

在项目索引登记档案，主方案按阶段引用；平台事实只在档案维护，主方案保留选用平台、阶段需求和引用。保存在本地文件才能跨聊天复用，不能只说“已记住”。跨项目复用时读取用户指定或已明确关联的本地共享档案；不自动建立全局台账、不把一个账号的路径套给另一个账号。

### 保存内容

可参考 [环境档案模板](../assets/hpc-environment.md)，只取当前已知信息与影响任务的待确认项，不复制整张空表：

| 信息组 | 应保存的实际内容 |
| --- | --- |
| 身份与适用范围 | 稳定平台标识、适用账号/项目或环境名、OS/架构与 shell；登录节点/计算节点的差异（如已知） |
| 超算文件环境 | 项目、提交/工作、临时盘、数据/模型/赝势及结果目录；共享范围、计算节点可见性、读写约束、临时盘清理/保留规则 |
| 软件位置与启动 | 引擎/框架版本、可执行文件或命令、Python/Conda/venv 前缀及解释器、module/容器位置、启用顺序、MPI/调度启动方式、模型插件与 CPU/GPU 构建 |
| 调度与资源 | 实际调度器、适用模板、队列/分区及平台要求的账号/QoS、任务/线程/GPU/内存/时限约束 |
| 本地→超算映射 | 本地准备包/输入位置 → 用户放置的超算目录，目标机已有依赖及回传资料 → 本地结果接收目录 |
| 来源与有效性 | 档案修订标识/日期，各重要条目的来源、确认日期、确认范围/状态，适用的软件/脚本版本、冲突与待确认项 |

软件“目录”、实际“可执行文件”和“启用后才可用的命令”分开写。不知道绝对路径时可保存用户提供的 module、环境名称或调用命令并注明限制，不能编造安装位置。模型/赝势文件位置与软件安装位置也不混为一谈。只记录运行所需的非秘密环境信息，不索取或保存密码、密钥、token 或完整未筛选环境转储。

### 读取、更新与确认

1. 准备新脚本、恢复聊天或收到追问时，从索引/主方案定位档案，核对平台、账号和阶段；沿用仍适用的条目，不重新收集整套资料。
2. 用户提供的文字、拷回的目录/软件清单、历史作业脚本、平台指南和回传日志都是可保存来源。原脚本仅读取，不执行或 source；冲突保留范围与依据，只追问改变当前输入/脚本的项。缺失信息可请用户提供针对性的文本输出，不自动登录或全盘扫描。
3. 区分“用户提供”“文档/脚本静态提取”“用户回传运行证据”“待确认/过时”。记录确认日期不等于实测；旧作业成功只证明当时对象和环境，不升级为当前可用。没有证据不标为目标机运行已验证。
4. 新信息原位更新同一条目，重要变更简记日期与来源，复查路径/启用顺序/启动命令/资源及关联草稿。旧输入与历史运行仍保留其当时依据；不为一次环境追问新建一份档案。
5. 超算路径（包括 `~`、`$HOME`、`$SCRATCH` 等目标机表达式）始终按目标平台语义保存。不得在本地展开、创建、`ls`、`resolve` 或作 `exists` 检查来声称超算存在/缺失；本机 `which`/PATH 和包版本也不能填作超算软件证据。检查其可用性须由用户提供目标机资料。

环境档案不是执行许可证。准备目标脚本时说明引用的档案路径、修订标识/日期及确认状态；涉及的路径或版本仍冲突时，相关材料标为草稿，继续不受影响的工作。超算路径在文档中用代码文本记录，不伪装为可点击的本地文件链接。

主方案用简短的阶段映射关联这些信息：

| 阶段 | 方法/软件 | 平台档案/配置位置 | 本地输入与脚本 | 目标运行目录 | 脚本准备状态 |
| --- | --- | --- | --- | --- | --- |

当只存在一个阶段时，可用一段话表达，无需强制创建表格。方法未定、调度器不清楚、路径尚缺等问题在同一记录更新，不反复向用户索要已保存且适用的回答。

## 3. 只准备所选平台的文件

先确定计算内容与引擎输入，再根据目标平台生成环境启用、资源请求、引擎启动、工作路径和日志设置。两部分有兼容性约束；移植平台时要检查资源和软件构建对科学设置的影响，不能保证只改文件后缀即可运行。

建议文件名仅作为项目约定，扩展名不决定调度器：

| 目标环境 | 可采用的本地文件 | 适配要点 |
| --- | --- | --- |
| 无调度器的本机/工作站 | `run_local.sh`，或目标系统需要的启动文件 | 按目标 OS、shell、环境和设备启动；不带其他平台的调度头 |
| Slurm | `submit.slurm` | 使用经核实的 Slurm 资源指令，环境与引擎启动遵守本平台模板 |
| PBS | `submit.pbs` | 核实 PBS 的实际实现与资源语法，不机械翻译 Slurm 参数 |
| LSF | `submit.lsf` | 核实 LSF 的资源与提交方式，不照抄 Slurm/PBS 头部 |
| 自定义系统或包装器 | 按已知平台规范命名 | 阅读该平台文档或现有模板，缺信息时不伪装成通用可运行脚本 |

查证入口：[Slurm sbatch](https://slurm.schedmd.com/sbatch.html)、[ALCF PBS 指南](https://docs.alcf.anl.gov/running-jobs/)、[IBM LSF 脚本提交说明](https://www.ibm.com/docs/SSWRJV_10.1.0/lsf_command_ref/bsub.category.script.1.html)。实际生成脚本时读取目标平台和软件适用版本的资料；这些链接本身不构成兼容性证据。ALCF 的队列和资源规则不能作为所有 PBS 机器的默认值。

只生成已选择的平台所需文件，不为同一任务同时铺开所有调度器模板。多个平台确实需要保留时，可在 `input/<体系>/<阶段>/draft/<平台标识>/` 下分别准备；单平台沿用现有草稿布局。脚本标明目标平台、关联方案及平台记录，避免误用。

## 4. 本地准备与目标执行之间的路径

- 区分本地准备根目录、目标提交位置、计算工作目录、临时盘和最终结果目录。命令中不混入本机绝对路径与远程路径。
- 超算绝对路径可以出现在本地生成的目标脚本文本中；本地文件写入目标始终是本地项目路径。共享盘、临时盘和模型引用只按档案中的目标机约定使用。
- 检查模型、赝势、程序和相对脚本依赖在目标环境如何获得；不把本机已安装误当成超算已安装。
- 交付说明列出准备包包含什么、平台端需预先具备什么、文件需放到哪里，以及用户准备执行的命令。命令的说明不代表执行授权。
- 对超算明确列出用户手动传输/执行入口及需要回传的日志、实际输入、模型/环境版本和分析所需结果。本地分析接收目录与超算结果来源对应；未回传的文件标为未取得，不从本机探测替代。
- 按目标调度器与文件系统文档核查文件可见性；提交脚本不能代替输入、模型和依赖的传输或共享存储安排。
- 用户允许准备文件，不代表允许上传、修改远端文件、占用登录节点或申请作业资源。已有明确授权按范围继续有效。

## 5. 缺信息、检查与变更

若平台选择尚未确定，继续完成不依赖平台的科学方案和输入设计，把具体启动材料标为待补全。不猜测分区、账号、module 名称、安装路径、MPI 启动方式或 GPU 数量。

如用户需要先看脚本骨架，明确标为未完成草稿；若包含待填配置，执行前须检查缺项并在调用引擎前退出。不能依赖脚本内的退出逻辑阻止调度器接收作业或分配资源，仍不得提交未经授权的草稿。

可在检查工具本身无副作用的前提下做静态语法/配置审阅；不通过 source、执行脚本、模型加载、调度提交或 smoke test 来“验证”。本地语法通过不证明目标机器资源、环境和运行已验证。

交付时把方案准备、文件准备、科学证据与执行授权分开记录。静态检查通过而未在目标机实测的脚本，如实标明“静态检查通过，目标机运行未验证”，不能宣称已测试可运行。

切换平台、调度系统、软件构建、运行路径或资源后，回写原平台记录及受影响脚本，复查路径、环境、资源与引擎兼容性，并判断已有授权是否仍覆盖。不默默沿用旧平台脚本。
