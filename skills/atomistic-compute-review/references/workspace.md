# 工作区与知识维护规则

## 1. 先识别，再写入

确认用户指定的计算项目根目录，读取适用的项目指令、目录和文档索引。发现 `analysis/`、`notebooks/` 等已有布局时使用对应目录，不另造同义目录。已有主方案不在 `docs/` 时可以原地维护并建立索引链接。

此处的项目根目录及 Codex 的文件写入位置均为本地目录。超算目录仅记入本地环境档案和目标脚本文本，不在本机创建同名绝对路径，也不把档案路径传给本地初始化工具。超算运行的日志/结果由用户回传后，在本地按来源运行归档。

本规则不授权批量移动、重命名、删除、合并历史文件或改写既有程序的路径。存在重复文档时，指定一个主维护入口，其余保留并在适当位置标注链接；批量清理另行处理。发生命名冲突时选安全的新位置或说明具体冲突，不能覆盖。

如果只是咨询或只读检查，不为了整齐改造已有项目。新项目开展持续方案设计，或首次准备项目产物时，默认初始化核心目录。默认建立五个目录；先不创建空的专题文档和完整模板。

## 2. 目录分工

| 路径 | 放什么 | 边界 |
| --- | --- | --- |
| `docs/` | 当前方案、项目配置、主题知识、依据、决定、未解决问题和索引 | 项目配置默认融入主方案；同一内容只维护一处 |
| `notebook/` | `.ipynb`，用于交互分析、解释或展示 | 默认不执行；可复用逻辑放 `analyse/`，输出按下述路由保存 |
| `analyse/` | 分析脚本、小型分析程序、可复用绘图和后处理代码 | 不存第三方软件安装包、环境或计算输出；不因编写就执行 |
| `input/` | 结构、训练/引擎配置、模型接口设置和启动脚本草稿 | 按体系/阶段及必要的平台组织；已用输入不随新草稿改变 |
| `output/` | 实际计算输出、运行日志、由已有结果产生的数值分析产物 | 按体系/运行标识组织；没有运行就不制造结果文件 |
| `figures/`（按需） | 导出的图表和结构示意图 | notebook 内联展示不必额外复制；与来源运行建立链接 |
| `references/`（按需） | 原始论文、补充材料、来源清单和原始资料 | 解释与决定回到所属 `docs` 主题；不是每篇论文强制生成 Markdown |
| `data/`（按需） | 外部参考、训练、验证和实验数据集 | 仅实际需要时创建；引擎输入去 `input/`，本项目模拟原始输出去 `output/` |
| `models/`（按需） | 项目所需模型说明、已提供的权重或检查点引用 | 不自动下载、复制大权重或加载推理；可链接外部位置 |
| `archive/`（按需） | 明确被替代且仍有保留价值的阶段快照 | 不按对话轮次备份；不自动迁移历史材料 |
| `tmp/`（按需） | 可识别用途的临时中间产物 | 不自动清理未知内容；正式依据和唯一结果不只留在这里 |

运行日志默认跟随 `output/` 中的具体运行，不另建一个竞争性的全局日志目录。图表、数据和模型目录在需要时创建，避免空目录膨胀。输入生成程序可以放 `analyse/` 下的准备工具子目录，但必须与提交逻辑分开。

### 简单项目示例

```text
project/
  docs/
    index.md
    plan.md
    topics/
      magnetism.md
  notebook/
  analyse/
  input/
    system-a/
      draft/
  output/
  figures/                 有导出图表时创建
```

这是可选示例，不能据此自动创建 `system-a`、示例专题或结果文件。多体系时将 `input/`、`output/` 按稳定体系标识分开，单次运行再分目录。复杂阶段按需要细分，不给每种可能计算预建目录。

运行文件的原生共置要求优先。用户批准执行时，运行目录可以放在 `output/<体系>/<运行标识>/`，其中保留该次实际使用的输入、日志和输出；无需为了扩展名分类拆散引擎工作目录。后续分析产物放该运行的 `analysis/` 子目录，公共分析代码仍在 `analyse/`。

原始结果和已用输入不就地修改；新分析写新产物，新的输入变化留在新的草稿/运行版本。旧运行不因重试自动删除。用户未授权执行前，不复制材料到可触发计算的目录。

## 3. 一个入口，少量持续维护的文档

优先沿用已有索引和主方案。新项目默认：

- `docs/index.md`：简短说明研究目标、当前可靠结论、主要阻碍与下一项优先行动，链接当前方案、已存在的专题和主要产物；不复制详细论证。
- `docs/plan.md`：当前研究问题、项目配置、方案选择与依据、阶段交接、未解决项、验证/停止计划，以及方案准备、文件准备、科学证据与执行授权。首次存在实际方案内容时才创建。
- `docs/topics/<稳定主题名>.md`：只有能长期独立维护、值得单独检索的主题才建立，例如磁序选择或某个模型适用性。短问题直接补充主方案中的对应小节。

普通本机平台配置可融入主方案；超算环境在本地持久保存为 `docs/platforms/<平台标识>.md`，已有 `docs/platform.md` 等对应说明原位复用。首次取得实际超算信息即归档，索引登记、主方案按阶段链接；后续先读档案、回写同一位置，平台目录和软件位置不再复制进主方案，细节见 [平台适配](platform.md)。项目科学配置也不强制再复制成 YAML/JSON；实际工具需要配置文件时，记录其对应方案版本并核对参数。

多项相互独立的研究计划可采用 `docs/plans/<研究标识>.md`，由索引指定各自范围；不要为同一计划的每个阶段或每次追问新建主方案。已有文档继续使用稳定路径，不按日期反复生成同义文件。

一般不另建 `notes/`、`qa/`、`decisions/`、`reports/` 来复制同一批知识。决定和问题记录放在所属方案或专题；用户要求独立报告时再导出明确标注的快照，索引仍指向当前主文档。

## 4. 每次追问的处理流程

1. **检索。** 先读索引和当前方案的相关段落，再按主题、同义词、体系和目标量搜索已有 Markdown。不要每次遍历大型轨迹、权重和所有原始输出。
2. **判定范围。** 比较科学问题、体系、相态、温压、电荷/磁性、方法与参考态。措辞相似不代表条件相同；措辞不同也可能是同一主题。
3. **选择归属。** 优先更新已有段落。只有新主题可独立复用、与主线范围实质不同，或原文已因多条独立论证难以导航时，才建立专题并在索引登记。长度本身不触发机械拆分；先改善摘要和小节。
4. **更新结论。** 相同信息无需再写；补充证据放在原结论附近；重要修正同时更新前置摘要与受影响的主方案。已否决的路线标记为已否决，不混在当前推荐中。
5. **处理历史与冲突。** 结论改变时记录日期、变更点和原因/来源即可，不复制整段旧答案。未能解决的冲突并列记录适用条件及待查证项，不悄悄改成新事实。日期使用用户时区。
6. **检查关联。** 当前方案依赖的结论发生变化时，同步修正依赖或标记待复审；只有结构、方法、关键参数、阶段、运行平台或资源范围实质变化才更新方案版本，并重新判断授权范围。平台改变时复查环境、路径和启动脚本。拼写或表述调整无需新版本。
7. **简短反馈。** 告知本轮结论、未解决项和修改位置；只展示影响用户决策的变化，不把主文档全文重新贴到聊天中。

不要把“提出过某问题”本身保存成一个新文件，也不要将新答案无限追加到文末而留下过时摘要。目标是维护当前可读的知识，不是积累逐轮转录。

## 5. 记录格式与知识状态

条目保留其实际需要的信息：问题/主题、适用范围、当前结论、状态、证据或用户依据、对方案的影响、待解决项。短条目可用几句话，复杂主题才使用表格。不为每条随口回答套完整模板。

区分以下语义：

- **已核实事实**：有可定位的数据或来源；用户提供的信息标为“用户提供”，未经独立核实不升级。
- **假设 / 候选方案**：尚未验证，说明用途与限制。
- **用户偏好 / 已作决定**：注明由谁决定及范围；决定不等于科学事实或运行批准。
- **待确认**：需要补充信息或澄清冲突。
- **待计算验证**：有明确的验证设计，但没有运行结果。
- **已否决 / 已替代**：保留简短理由及当前结论的链接。

稳定问题编号适用于长期跟踪的开放问题，不必给每轮聊天或每句话编号。引用原始证据的路径、图表、输入/模型版本；不要把 Markdown 中的猜测当作新的外部证据。

### 同一主题的连续追问示例

“是否考虑磁性？”、“是否比较 AFM？”、“当前 MAGMOM 如何设？”通常都应更新同一主方案的磁性小节，或已有的 `docs/topics/magnetism.md`。当前推荐和未确认项始终在前。

若另一个体系具有不同组分、条件或研究目标，先区分适用范围，再决定使用同文档的独立小节还是独立计划。不要把两个体系的相反结论合并成一个通用建议。

## 6. 初始化工具

在新项目的既有根目录使用：

```bash
python /实际skill路径/scripts/init_workspace.py /实际项目根目录 --check
python /实际skill路径/scripts/init_workspace.py /实际项目根目录
```

上述路径是调用说明，使用时替换为实际路径，不照抄占位文本。工具只依赖 Python 标准库，创建五个核心目录和缺失的 `docs/index.md`，不创建主方案、执行模拟、移动文件、安装依赖或下载模型。重复调用不覆盖已有索引。

`--check` 只报告将创建/保留的项目。工具不做语义归类或自动识别同义目录；代理先完成布局判断。遇到路径冲突或目标子路径为符号链接时拒绝初始化，由代理查明实际布局后处理，不自动替换链接。
