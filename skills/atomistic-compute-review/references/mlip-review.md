# 数据、训练与模型部署审查

按当前入口读取相关小节。已有合适模型时不默认训练；只有结构时不把格式转换当成获得标签。检查项服务于目标性质，不要求所有项目填满清单。

## 1. 数据来源与参考口径

先读已有清单、格式说明和小规模样本，不一次扫描全部大型数据。记录实际位置、来源/版本、体系与构型范围、帧/原子数量及可用标签；大型数据可引用外部路径，不自动复制或下载。

- 区分结构集合、带标签数据、模型预测的伪标签和实际参考计算。目标训练需要哪些标签由性质、损失项和框架确定，不能统一要求所有数据都有全部标签，也不能静默补零代替缺失标签。
- 检查帧与标签、原子顺序和元素映射对应，维度、缺失值/非有限值、单位和归一化一致。区分总能量/每原子能量、力、应力/virial 的符号、分量顺序与体积约定；不能只重命名字段来转换物理量。
- 参考标签追到泛函、赝势、磁性/电荷、U/SOC 等适用物理选择与数值收敛。不同口径先分组并说明可比性，不能无说明混成同一精度来源；需要 DFT 时参见 [DFT 审查](vasp-review.md)。
- 检查重复构型、异常几何、异常能量/力及来源组重叠。异常先解释或隔离并保留索引，不直接删除原始数据，不把高力构型一概判为坏数据。
- 对目标组成、局部环境、相态、温压、缺陷、表面及反应路径给出覆盖证据和缺口。新增采样、标注的范围、预算和停止条件写进方案，不能自动执行。

[DeePMD 数据说明](https://docs.deepmodeling.com/projects/deepmd/en/latest/data/system.html) 给出其自身字段、形状与单位约定；不把这些约定推广到所有框架。实际转换前核查所选版本及目标加载器。

## 2. 划分、训练与微调准备

1. 按科学问题选择按轨迹、母结构、来源或条件分组的划分策略。检查近邻帧、同一母结构衍生构型及重复样本跨集合的泄漏风险；记录划分版本、来源索引、处理步骤和适用的随机种子。
2. 留出用于最终报告的测试集，不用其结果反复选择超参数；数据太少时说明评估限制，设计适合来源结构的分组交叉验证或追加数据计划。
3. 比较已有模型、微调和从头训练的必要性：目标元素/性质、数据量及标签、参考理论、可用设备与预算、许可及部署接口。只保留有实质取舍的候选；不凭框架名承诺精度。
4. 需要微调时核对基座权重与配置、任务头、元素覆盖、标签口径及所选版本支持的微调方式。需要训练时准备目标加载器可读的数据引用及配置草稿；未知的关键字段标为待确认，不生成冒称可用的配置。
5. 配置只包含所选框架实际支持的参数：目标损失及权重/单位、批次策略、学习率/调度、步数或轮数上限、检查点/恢复、精度/设备、随机过程。数值依据数据尺度、官方说明或已有基准确定，不硬编码“通用准确参数”。
6. 在看测试结果前定义基准、验收、过拟合/不稳定诊断、预算及停止条件。异常或失败后的策略形成建议，不自动重试、扩预算、换模型或启动主动学习。

交付包括数据可用性/缺口、划分依据、路线选择、训练/微调配置和验证计划中当前任务需要的部分。没有实际训练就不生成权重、性能结果或“训练成功”的记录。

## 3. 已有模型及适用范围

记录具体模型、权重来源/版本或校验值、配套配置、框架版本、任务头、许可/获取前提和已提供的验证资料。仅阅读已有安全元数据；不能用加载模型、反序列化不明权重或执行其下载器来收集信息。

- 元素在支持列表、文件能加载、结构能优化，都不单独证明适用。核对目标局部配位、相态、温压、缺陷、表面、反应或电荷/磁性变化的实际证据。
- 核对模型训练参考与项目参考口径的关系，以及能预测的量。不能把能量/力模型扩展为未经支持的电子性质或机理证明。
- 检查能量零点、归一化、力和应力约定，跨组成比较与目标参考态；不直接混用不同模型的能量零点。
- 优先目标体系、目标性质和困难构型的已有基准。总体平均误差不代替目标性质、候选排序或筛选阈值附近漏选风险的验证。
- 模型间分歧/不确定度未经校准时只作预警，一致不等于正确。单次稳定运行也不证明目标域内可靠。

官方模型卡、原始论文和固定版本说明优先；例如 [MACE 模型资料](https://mace-docs.readthedocs.io/en/latest/guide/foundation_models.html)。链接是查证入口，不表示特定模型已通过本项目验证。

## 4. 验证计划与导出部署

缺证据时选择能检验当前关键假设的代表构型、参考标签和目标性质，写明误差定义/单位、构型分组、验收阈值的依据、不通过后的处理和资源上限。区分静态误差、结构优化、有限温度动力学、势垒及目标性质各自所需证据。

部署前核查完整链条：**权重与配置 → 框架/导出工具版本 → 导出产物 → 引擎及具体接口/插件构建 → 设备/精度 → 元素映射与输入**。文件扩展名或“支持 LAMMPS”不足以证明兼容。

- 对所选接口查官方版本资料，记录查阅日期、目标版本与支持状态：已查证可准备、需要版本核查或暂不支持。没有对应适配时交付明确缺口，不临时编造命令。
- 导出步骤只准备命令和前提；若实际运行会加载/执行模型、调用设备计算或下载，按主 skill 的执行/环境边界处理。
- 原框架与目标引擎的一致性验证选择相同构型，比较约定一致的能量、力及任务需要的应力等量，定义容差与依据。它是待授权数值验证，不能用静态检查替代。
- 模型、任务头、接口、精度或设备变更后，复查导出与验证是否仍适用，标记受影响下游材料；保留历史已用产物与结果。

接口入口：[MACE ML-IAP](https://mace-docs.readthedocs.io/en/latest/guide/lammps_mliap.html)、[DeePMD–LAMMPS](https://docs.deepmodeling.com/projects/deepmd/en/latest/third-party/lammps-command.html)。2026-11-06 查阅时，MACE 页面区分两条 LAMMPS 接口并对 ML-IAP 导出列出 GPU 前提；这正说明导出不能统称为纯文件转换。具体命令与依赖在项目采用时重新核查，不在本 skill 固定成通用模板。

部署后的结构、引擎输入与结果分析见 [模拟与分析](simulation-analysis.md)。只批准一次验证不扩展成训练、长 MD、参数扫描、正式标注或自动迭代。
